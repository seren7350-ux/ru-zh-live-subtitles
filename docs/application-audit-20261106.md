# 应用与老师要求复核（2026-11-06）

本轮只读审查生产源码，没有修改应用行为。检查涵盖 Windows 窗口、字幕排版、设置、进程生命周期、日志与 SRT；51 个 Python 源文件通过 AST 解析。用隔离 Tk 实例测量完整设置布局、最小窗口工具栏；测试实例已销毁，没有加载模型或开启麦克风。此前 183 项相关回归与 37 组原生验证作为既有证据，本轮没有重新运行完整 pytest。字幕层源码哈希与此前原生验证一致。

结论：老师要求大多已有对应实现，尚不能称为完整验收的应用。优先问题是控件可达性、设置组织与配置保存；上轮修复的移动/闪烁没有发现新的反例，但本次不扩大其已验证范围。

## 已确认问题

1. **P1：最小宽度会挤掉 Settings 和 Exit。** `gui/overlay.py:689` 先 pack 状态标签，再 pack 按钮。原生 Tk 探针使用允许的 520px 宽度和 `Listening... 麦克风 (HyperX Cloud III) (1 channel, 44100 Hz)`，结果 Settings 与 Exit 的 `winfo_ismapped()` 均为 false，Pin 也被压缩。建议为操作按钮预留固定区域，状态文字截断或省略，完整设备名放入设置。
2. **P1：设置页没有适应小屏的布局。** `gui/overlay.py:222` 将设备、模型、操作按钮、路径、定位和四个滑块放进单一纵向 pack。使用完整模拟设备/模型/SRT状态，三个 Tk scaling 取值 1.0/1.333333/1.666667 的请求高度分别为 868/1169/1124px。该测量仅代表测试字体与桌面环境，不对应所有 Windows 缩放比例；已足以说明其无法保证在 768px/1080px 可用高度内完整显示。应使用分组或分页、工作区高度限制；必要时允许设置内容滚动。老师禁止的是字幕历史纵向滚动，不是设置页滚动。
3. **P2：Floating 是无效果按钮。** `position_coordinates()` 在 floating 分支直接返回当前坐标；Top/Bottom 也没有锁定或吸附行为。测试输入 (321,456)，返回仍为 (321,456)。建议删除 Floating，改为“移到顶部”“移到底部”两个动作；自由拖动始终可用，不再把它包装成模式。
4. **P2：用户设置不持久。** `SubtitleViewState` 保存内存状态，启动时重新使用默认值/CLI参数，未见配置文件读写。字号、透明度、描边、位置/大小、设备选择等跨应用重启不能自动恢复。Settings 的 `last_geometry` 也只在同一进程有效。建议区分“用户偏好”和“会话状态”，只持久化前者，恢复窗口时检查有效工作区。
5. **P2：定位预设忽略当前显示器工作区。** `position_coordinates()` 接收主屏尺寸，用固定 top=20、bottom=70px 安全距离；没有当前显示器、任务栏实际工作区或拔掉外接显示器后的恢复逻辑。多屏/DPI组合仍需单独验收，不能由负坐标测试推导全部支持。
6. **P2：故障日志覆盖仍不完整。** 应用与worker的 Python 异常栈、阶段、会话和退出码已有记录；源码未发现 faulthandler、原生崩溃转储、卡死线程栈采集。原生扩展直接崩溃或引擎一直存活但不响应时，现有日志未必能说明内部原因。建议补充诊断机制与用户可打开的日志入口，同时保留字幕文本脱敏。
7. **体验问题：每次 Start 都重新加载模型。** `LiveProcessOverlayController.start()` 新建工作进程，Stop 退出；这有隔离故障、释放资源的理由，但带来冷启动。2026-11-06 的实际日志显示从 Start 到 Listening 约49秒，其中 ASR准备约42秒。需要显示当前准备阶段和可取消状态；若以后保留预热worker，应先明确稳定性和内存取舍。

## 设置页面建议

主窗口只保留开始/停止、简短状态、设置和关闭；置顶可保留为紧凑操作。设置分为：

- **常用：** 麦克风、显示俄文、置顶。
- **字幕外观：** 两种字号、背景透明度、文字透明度、黑色描边。开关使用复选框/切换控件，不再全部使用同样的宽按钮。
- **更多：** 移到顶部/底部、窗口边框、恢复默认、字幕保存位置。
- **诊断：** 模型状态、重新检查、模型目录/安装说明、日志入口。正常时只显示简短就绪状态，故障时提供明确修复入口。

Start/Stop、Clear、Exit 属于操作，不应继续与每个偏好选项混排。工具栏隐藏/全透明时仍需可达的开始、停止、关闭和恢复控件，可保留紧凑的辅助控制区。SRT默认自动保存，界面显示“已保存”与打开文件夹即可，不必长驻完整路径。统一界面语言和术语。

## 实际运行证据与边界

最近一次用户会话日志显示 5 条字幕成功、0条失败，无丢块/序列缺口，停止后麦克风和worker正常退出，应用退出码0。中文延迟P95约4.16秒；这只描述该次短会话，不代表识别准确率或长时间课堂实时性已经验收。持续讲话、不同麦克风与噪声仍需专项测试。

源码使用进程隔离模型、GUI事件消费、原生独立字幕透明层的方向合理，无须为了“像应用”而直接重写全部框架。风险在于窗口生命周期和状态逻辑复杂，测试不能仅依赖fake；此前移动/闪烁问题已经证明这一点。应继续保留原生矩形、静止事件次数和真实鼠标验证。

当前启动的是修复后的源码；旧发布安装包尚未重建，不能将源码验收结果当作安装包验收结果。本轮没有修改生产代码、启动录音、清理旧文件或重新运行大量测试；只新增本审查报告。
