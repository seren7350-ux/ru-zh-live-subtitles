# 字幕工具 UI 设计方向

状态：实施中；用户已明确要求深色主题。与 ui-redesign-goals.md 配套。

## 定位

字幕是内容，控制界面是短暂使用的工具。借鉴 Apple 的清楚层次、克制装饰、即时反馈与一致性，在 Windows 保留原生标题栏、窗口控制和键盘行为。不是给现有窗体刷色，也不仿制 macOS 红黄绿按钮。

参考：https://developer.apple.com/design/human-interface-guidelines/windows

## 设置窗的结构

采用一个尺寸稳定、紧凑的双栏窗口，初始目标约 680×520 逻辑像素，按实际内容与工作区验证调整。左侧约 144 像素的安静导航区，右侧是设置内容，不再使用浅色 Notebook 标签条和层层白框。切换页面不改变窗口位置或突然跳动高度。

导航只有三个主项：字幕、输入、窗口与保存。底部放“诊断与关于”，视觉权重降低但仍可键盘访问。

默认打开“字幕”：直接按语言、字号、背景、文字组织设置。用户明确取消设置内预览，真实字幕窗口提供即时反馈。滑块变化立即影响真实字幕并保存，不增加 Apply/OK；重置针对当前页，通过轻量确认避免误触。

当前页重置保留界面语言：字幕页只重置显示俄文、字号、背景／文字透明度和描边；输入页只恢复系统默认设备，运行／准备／停止期间禁用；窗口与保存页恢复置顶、边框、工具栏及初始位置尺寸，不修改字幕外观或已有 SRT。诊断页不提供重置。确认默认选“否”。

一行一项：标签左对齐；开关、数值或选择控件右对齐。连续量使用细轨道、清晰的实心滑块和固定位置数值；数值可键盘编辑并校验范围。百分比与字号单位明确。不要用数值随滑块移动的布局。分组靠标题、间距与细分隔线，无需每组都套卡片。

“字幕”页内容：显示俄文、俄文字号、中文字号；背景不透明度；文字不透明度、黑色描边。0% 明确标注不可见，保留简短不可见提示，真实窗口即时显示透明度变化。

“输入”页内容：输入设备选择及旁侧刷新、当前就绪／加载／监听／错误状态、一个开始／取消／停止主操作；模型正常时只显示简短就绪摘要，缺失或失败才提供处理入口。技术路径与加载详情折叠到诊断。用户不必理解模型内部名称才能开始使用。

“窗口与保存”：字幕置顶、无边框、显示工具栏；“移到顶部／移到底部”是一次性动作，不伪装成持续位置模式；SRT 自动保存说明与打开目录。快捷键用紧凑帮助入口，不占据常驻大段文字。

“诊断与关于”：版本／构建标识、模型详情、日志目录、导出诊断。恢复默认与退出不做每页底部的红色大按钮。设置窗关闭按钮只关闭设置。

只在内容确实超出可用高度时显示垂直滚动条；隐藏滚动条不影响键盘焦点可见性。小工作区允许滚动，正常尺寸不能出现无行程的白轨道。

## 视觉语言

设置默认采用深色：炭灰导航背景、略亮的内容区、柔和白色正文、次级灰文字、单一蓝色强调。字幕背景保持用户独立设置的深色透明层。设置不是字幕的延伸，不必为了统一而也做成黑色。

字号以系统 UI 字体为主；正文约 13–14 逻辑像素，页标题约 20，分组标题约 13–14 加重。按实际 Tk 字体单位和 DPI 转换，不直接把像素当 point。8 像素间距基准，组间 20–24，行高 36–40，外边距 20–24。控件统一圆角程度与边框，清晰悬停、按下、禁用和键盘焦点。红色只用于错误或真正需要警惕的动作。

先确保对比、内容密度和交互正确，再考虑轻微阴影。此次不引入玻璃模糊、发光、背景动画或逐帧透明合成；这些不解决现有问题，还可能增加窗口同步风险。

## 字幕窗

双语文字仍是主要内容。减少大面积装饰边线，工具栏收窄到足够容纳状态和操作。开始／停止作为一个有文字的清晰按钮；设置与置顶使用可理解的图标并提供提示和键盘入口。退出放进更多菜单，避免常驻红色按钮干扰阅读。双击隐藏工具栏行为保持，不引入会与拖动冲突的自动隐藏。

## 窗口激活规则

显式打开设置时将其前置，初次优先放在字幕上方的可用工作区，避免直接压住字幕；记住用户移动后的合法位置。设置为非模态工具窗口。点击字幕时字幕背景与文字作为整体前置，设置不得再抢回；点击设置则设置前置。字幕的“置顶”针对其他应用，不意味着设置永远盖住字幕。关闭设置不停止引擎，透明到 0 时仍有任务栏／快捷键可恢复操作。

这些规则必须通过原生 owner/激活策略实现并实测，不靠频繁 lift()/focus() 纠正。Windows topmost 与 owned-window 约束需先做小范围原型；若冲突必须调整窗口归属，不能仅改焦点颜色假装完成。

## 实现边界与评审顺序

先制作视觉原型：正常设置、设备错误、加载／取消、零透明度、缩小窗口五种状态。原型通过后才迁移真实控件。保留现有状态与回调接口，主要修改 settings_pages.py、settings_panel.py；主题可独立模块。主窗仅调整 overlay.py 的呈现，窗口交互修改 coordinator/必要的 caption layer。纯样式迭代不触碰音频、ASR、翻译、SRT、进程控制。

现有 Tk/ttk 可以完成层级、排版和大部分控件风格，但不能承诺不增加控件封装就达到苹果原生控件的视觉精细度。是否需要少量自绘取决于原型验证；不默认迁移 Qt、WebView 或整套 GUI 框架。自绘必须保留键盘、焦点和高 DPI 行为。
